# GITHUB PAGES

> **Status: diagnostic host only. It cannot serve this application's security policy.**
>
> The supported production host is Cloudflare Pages — see `docs/TESTNET_HOSTING.md`
> and `wrangler.jsonc`. Read the "Headers" section below before deploying anywhere
> that is not Cloudflare Pages.

## Deployment

- Build static frontend: `pnpm run build` in `apps/web`.
- Output: `apps/web/dist/` (HTML, JS, CSS, plus the generated `dist/_headers`).
- The workflow is `.github/workflows/pages.yml`. It runs **only** on manual dispatch and
  refuses to publish unless `acknowledge_no_security_headers` is set, because the publish
  step below cannot deliver the headers the application requires.

## Headers — what GitHub Pages does NOT send

GitHub Pages cannot serve custom HTTP response headers. The `dist/_headers` file generated by
`apps/web/scripts/write-deployment-headers.mjs` is copied into the artifact and then **ignored**.

A GitHub Pages deployment therefore has *no*:

| Header | Consequence of its absence |
| --- | --- |
| `Content-Security-Policy` (with `frame-ancestors 'self' https://universe.tari.mw`) | No inline-script restriction and **no clickjacking control**; any origin may frame the signing UI |
| `X-Content-Type-Options: nosniff` | Content sniffing on bundle/metadata responses |
| `Cross-Origin-Opener-Policy` / `Cross-Origin-Resource-Policy` | Cross-origin isolation the policy relies on is missing |
| `Referrer-Policy: no-referrer` | The referrer is sent on outbound requests, including metadata fetches |
| `Permissions-Policy` | No feature-restriction policy |

So any earlier statement that a "CSP header is enforced" on this host was **false** and is
withdrawn: CSP enforcement is an observed-response property (finding R-1) that can only be
confirmed on a host that can send the header. Do not treat a GitHub Pages URL as equivalent to the
Cloudflare Pages deployment, and do not use it to demonstrate R-1 closure.

## What remains true on this host

- All bundled JavaScript is PUBLIC. No secrets in the build.
- No remote executable scripts; no analytics, no tracking.
- Dependency pinning: lockfile committed, `pnpm install --frozen-lockfile`.
- The application still refuses mainnet, still gates real cross-chain submission OFF, and still
  re-reads chain state authoritatively before signing — the deployment host does not relax any of
  that. The headers are an *additional* control layer, not the only one.

## Signing boundary

- Signing requires a Tari wallet provider injected in the page; the website never receives private
  keys or seed phrases.
- The wallet adapter keeps preview and signature on the provider's side of the boundary.

## Build verification

- Verify `dist/index.html` exists and references only local assets.
- Verify `dist/_headers` exists and contains `frame-ancestors` (it will, on every host — but only
  Cloudflare Pages serves it).
- Verify no `.env` or secret files are present in `dist/`.
