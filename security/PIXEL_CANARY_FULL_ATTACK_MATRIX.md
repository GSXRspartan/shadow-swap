# Pixel Canary — full attack matrix

Independent adversarial pass over the whole repository, by an approach explicitly
*not* reusing the conclusions of the earlier subsystem matrices
(`CROSS_LAYER_ATTACK_MATRIX.md`, `MULTIHOP_ATTACK_MATRIX.md`,
`FRONTEND_ATTACK_MATRIX.md`, `LP_HISTORICAL_ATTACK_MATRIX.md`,
`DEPLOYMENT_SECURITY_MATRIX.md`, `MARKET_DATA_RESIDUAL_RISKS.md`). Those were read
as hypotheses; rows below that reuse them are marked with the evidence that was
re-executed here rather than trusted.

## Scope and method

- Every row was either (a) executed against the code by a test written in this
  pass, (b) re-executed from an existing suite, or (c) attempted and stopped by an
  external or tooling blocker that is named in the row.
- Evidence pointers are files in this repository, never narrative claims.
- `UNKNOWN` is not an allowed result. Where a risk could not be closed it is
  classified `EXTERNAL_RISK`, `BLOCKED_EXTERNAL`, or `BLOCKED_TOOLING`.

## Result legend

| Result | Meaning |
| --- | --- |
| `PASS` | The attack was attempted (here or by a re-run suite) and the invariant held |
| `FIXED` | A real defect was found in this pass, root-caused, fixed, and given a permanent regression |
| `N/A_BY_CONSTRUCTION` | The architecture makes the attack unreachable |
| `EXTERNAL_RISK` | Invariant holds locally; the residual exposure sits in an external system |
| `BLOCKED_EXTERNAL` | Closure requires infrastructure this environment does not have |
| `BLOCKED_TOOLING` | Closure requires a platform/tool this environment cannot run |
